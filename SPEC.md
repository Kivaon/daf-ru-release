# DAF-RU — постоянные решения

## Учебный принцип

Оригинал — основа. Пользователь указывает место в оригинале; приложение выделяет соответствующий смысловой блок и показывает точный русский перевод и отдельное короткое объяснение контекста. Объяснение не должно превращаться в длинный шиур. Оригиналы Гемары, Раши и Тосафот модель не дополняет и не исправляет.

Каждый комментарий имеет собственный ref, original, translation, explanation. Original берётся из источника, остальные поля — из учебного материала. Не объединять комментарии так, чтобы терялась связь с ref.

## JSON-контракт генерации

Обычный фрагмент:

```json
{"title":"…","translation":"…","explanation":"…","rashi":[{"ref":"Rashi on Bekhorot 2a:1:1","translation":"…","explanation":"…"}],"tosafot":[]}
```

Ответ модели — только валидный JSON, ASCII-кавычки для синтаксиса, экранирование внутри строк. Допустимое восстановление оформления при импорте не даёт права угадывать потерянный текст или незаметно изменять refs.

Существующее расширение для составной реплики:

```json
{"title":"…","parts":[{"ref":"11b:12","translation":"…"},{"ref":"12a:1","translation":"…"}],"explanation":"…","pages":[{"ref":"11b:12","rashi":[],"tosafot":[]},{"ref":"12a:1","rashi":[],"tosafot":[]}]}
```

UI добавляет tractate, выбранный ref, provider и unitRef. Поле pages исторически содержит refs частей, а не только номер страницы. Сохранять связь комментариев именно со своей частью. Не менять существующий контракт без совместимого перехода и проверки накопленных материалов.

## Идентичность и сохранность

- Идентичность статьи в БД, памяти UI и редакторе включает tractate + ref.
- Ошибка чтения не означает отсутствия статьи. Пока чтение не завершилось успешно, редактор не должен создавать замену неизвестному сохранённому материалу.
- Ответ отменённого запроса не обновляет выбранную статью.
- Черновик сохраняется под собственной идентичностью, а не под новым текущим выбором навигации.
- Один смысловой материал может охватывать несколько физических фрагментов, в том числе границу листа. Не вводить правило «один ref = одна статья».

## Сообщество

База накапливает проверяемые учебные материалы. Редакторы могут исправлять материал; готовый материал не генерируется заново при чтении. Целевой цикл: изучили → добавили/исправили → проверили → сохранили → используют другие. Существующие роли и upsert — лишь часть этого цикла; рецензирование и история редакций пока не реализованы.

## Следующие требования к проверке данных

Нужны единая проверка структуры JSON на клиенте и сервере, сверка refs с переданными источниками, уникальность комментариев и частей, точное соответствие parts/pages, отклонение потери содержимого вместо молчаливого обрезания. В пакетном режиме эта проверка реализована; обычный редактор и его API пока используют прежний контракт.

## Пакетная подготовка листа

- Лист означает выбранную сторону (например, 11b). В очередь входят все её реплики; пересекающая границу составная реплика входит один раз целиком, с комментариями обеих сторон.
- Перевод частей и общее объяснение используются повторно. Если Гемара уже готова, задание содержит только недостающие поля Раши/Тосафот. Полностью готовые статьи пропускаются.
- При сохранении составной статьи записываются все её части, включая соседнюю сторону. Комментарии остаются под собственными refs. Непустые опубликованные поля защищены от пакетной замены; исправления выполняются обычным редактором.
- Очередь и неопубликованные черновики принадлежат отдельному редактору и сохраняются в БД аккаунта. Они доступны после входа на другом устройстве; читатели их не видят. Публикуемые статьи остаются общими.
- Первый режим: копировать подготовленное задание в выбранный AI, вставлять ответ, проверять и нажимать «Сохранить и дальше». Прямые вызовы AI API не включены.
- Прогресс означает полноту сохранённых полей, а не автоматическую проверку качества перевода. Отсутствие комментариев подтверждается успешным ответом источника, ошибка загрузки не считается отсутствием.
- Конкурентное изменение очереди/статьи и несовместимые сохранённые части останавливают публикацию без потери или молчаливой замены материала.

## Восстановление и диагностика JSON

Оба редактора автоматически добавляют только недостающие конечные закрывающие скобки, если ответ становится валидным JSON без изменения текста. Отдельная кнопка больше не нужна. Незавершённые строки, значения, числа, пропущенные запятые и несовпадающие скобки не исправляются. После восстановления остаются проверки структуры, refs и полноты полей. Статья публикуется только по действию редактора.

Синтаксическая диагностика выполняется локально без AI и независимо от формулировки ошибки браузера. Показывает причину, строку/столбец, фрагмент с маркером, путь поля и ближайший ранее прочитанный ref. При неоднозначных кавычках причина обозначена как возможная. Типы полей, чужие и повторные refs проверяет общий importDraft в обоих UI; старый API одиночных статей отдельно ещё требует усиления.

## Карта перевода

Редакторский экран /translation-map доступен editor/admin. Каталог трактатов и диапазоны сторон берутся из talmudCatalog. Знаменатель — непустые исходные refs Wikisource Talmud Bavli из проверенного снимка Sefaria, никогда не число переводов. Одна единица карты — исходный ref на физической стороне; составная статья отражается на каждой своей стороне, поэтому суммы по строкам аддитивны.

Зелёный ref имеет сохранённый заголовок, перевод, объяснение и все переводы/объяснения Раши/Тосафот по источнику. Для составной статьи дополнительно готовы все её сохранённые части и их комментарии. Розовый — сохранённая неполная статья или непустой личный черновик любого редактора; совпадающие refs считаются один раз, готовое имеет приоритет. Пустое открытие очереди без введённого текста не создаёт розовый статус. Тексты и авторы чужих черновиков наружу не возвращаются. Белый — ref без статьи и черновика.

Доли равны ready/total, draft/total, missing/total. Полностью готовая сторона имеет total>0 и ready=total. Числа и проценты выводятся только по известным данным; ошибки источника или загрузки не равны нулю. Временная неизвестность обозначается штриховкой, общий неполный итог помечается ≥. Стороны после конца трактата не являются страницами и не имеют переходов.

Клик передаёт tractate/daf/prepare в URL, имеет приоритет над сохранённой позицией и автоматически открывает существующий пакетный редактор после загрузки источника. Email и Ready for review в эту задачу не входят.
